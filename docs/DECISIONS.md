# Принятые решения по открытым вопросам

Документ дополняет ТЗ (`plan.md`) и фиксирует договорённости, необходимые, чтобы MVP можно было
считать завершённым. Пункты 1 и 2 закрыты реализацией, 3 и 4 — решения на будущие этапы.

---

## 1. Формула итоговой оценки

**Решение.** Итог считается по взвешенной сумме баллов. Для каждого студента берётся набор
релевантных сессий (лабораторные — только его подгруппа, лекции/практики — вся группа), и для
каждой сессии:

```
w = activity.weight ?? subject.typeWeights[activity.type]   // по умолчанию лаб = 2, практ = 1, лекц = 1
m = activity.maxScore > 0 ? activity.maxScore : subject.scaleMax
s = выставленный балл либо 0, если оценки нет

finalPercent   = Σ (w × s / m) / Σ w × 100   // пропуски = 0 — это «итоговая оценка»
averagePercent = Σ (w × s / m) / Σ w × 100   // только сессии с выставленной оценкой
completion     = выставлено / ожидается × 100
```

Итоговая оценка = `finalPercent`, порог «сдал» = `subject.passThreshold` (по умолчанию 51%).
Порог проверяется по проценту от максимума занятия: занятие считается сданным, если
`s / m × 100 >= passThreshold`. Смешанная система «баллы + сдал/не сдал» реализуется через
`scaleKind = 'pass-fail'` (шкала 1) и тот же порог; отдельного порога «зачёт» по предмету пока нет.

**Почему пропуски = 0.** Иначе студент, сдавший одну работу на 100%, обгонял бы сдавшего все.
Именно это требование ТЗ («лабораторные значимее при равном количестве занятий») выполняет вес:
лабораторная с весом 2 даёт вдвое больший вклад и в числитель, и в знаменатель.

**Про пример из ТЗ.** «1 лаба = 100 баллов (вес 1.0), 1 практика = 100 баллов (вес 1.0).
Если сдано 2 практики и 1 лаба, итог = (100 + 50) / 200 = 75%» — в тексте смешаны две разные
метрики. В реализации:

| Сценарий | `averagePercent` | `finalPercent` |
| :--- | ---: | ---: |
| Оценены 2 практики (100 и 50), лаба не оценена, веса 1/1/1 | 75% | 50% (лаба = 0) |
| Оценены 2 практики (100 и 50) и лаба (100), веса 2 для лабы | 83% | 83% |

То есть 75% из примера соответствует **среднему по выставленным оценкам** при равных весах.
Обе цифры показаны в карточке студента: «средний по оценкам» и «итоговый балл». Если владелец
хочет видеть в журнале именно средний (без штрафа за несданное), это одна константа в
`src/domain/grading.ts`, но по умолчанию итог считается строго.

**Открыто на будущее:** отдельный порог «зачёт по предмету» (например, 70%) и правило
«лаб должно быть сдано не меньше N» — в ТЗ не заданы, в MVP не реализованы.

## 2. Что показывать в списке занятий на экране предмета

**Решение.** Строка занятия агрегирует **все** сессии занятия:

- количество сессий, «макс N · вес W»;
- прогресс `выставлено / ожидается` по всем сессиям (для лабораторных ожидаемое = 11 × 2 = 22);
- дедлайн последней сессии с бейджем «сегодня / просрочен / пройден · заполнено»;
- средний процент по занятию (в карточке занятия).

Детализация (даты, подгруппы, частичная заполненность) — внутри занятия, строки сессий со
статусами «заполнено / частично / не заполнено / предстоит». Разбивка по подгруппам в общем
списке не дублируется, чтобы не перегружать мобильный экран.

## 3. Бэкап на Яндекс.Диск

**Решение: не делаем.** В ТЗ выбран Google Drive через `drivestash`; Яндекс.Диск API — отдельный
OAuth, отдельная квота и отдельная библиотека, а выигрыш нулевой: бэкап уже страховочный, а не
основной канал. Пользователь при этом авторизуется через Яндекс ID только в Supabase — это
не даёт доступа к Диску. Если появится требование, добавляется второй `BackupTarget`
с тем же интерфейсом `push/pull`, без изменений в домене.

---

## 4. Напоминание подключить Google Drive

**Решение.** На этапе 3 — ненавязчивый баннер на вкладке «Данные» и в настройках:
«Бэкап на Google Drive не подключён», с кнопками «Подключить» и «Позже». Показывается не чаще
раза в 14 дней, закрытие запоминается в `localStorage` (`backupReminderDismissedAt`).
Push-уведомлений и модалок при запуске нет: приложение офлайн-первое, и напоминание не должно
мешать выставлению оценок на паре. Баннер скрывается навсегда, если пользователь включил
автоматический экспорт JSON или подключил Drive.

## Дополнительные решения, принятые при реализации MVP

| Решение | Обоснование |
| :--- | :--- |
| `HashRouter` вместо `BrowserRouter` | GitHub Pages не умеет SPA-fallback; hash-роутинг даёт рабочие deep links без 404 |
| PIN хранится как SHA-256 с солью в `localStorage` | PIN — секрет устройства, не синхронизируется; WebCrypto с фолбэком для небезопасного контекста |
| В JSON-бэкап не входят PIN и тема | Бэкап данных не должен переносить устройство-специфичные секреты |
| `maxScore = 0` у занятия = «наследовать шкалу предмета» | Позволяет менять шкалу предмета, не переписывая занятия |
| Дедлайн = следующее занятие группы/подгруппы | ТЗ: «дата следующего занятия у этой подгруппы»; учитываются все сессии предмета, а не только того же занятия |
| Дедлайн занятия = дедлайн его последней сессии | Для нескольких дат (подгруппы) важен финальный срок сдачи |
| Подгруппы создаются автоматически (2 шт.) при добавлении группы | Ускоряет настройку предмета; количество и названия меняются в данных |
| Импорт JSON: `merge` (LWW по `updatedAt`) и `replace` | Восстановление без потери более новых локальных записей по умолчанию |
| Импорт расписания из `web-schedule` | Повторное использование данных прошлого проекта: каждая дата пары становится занятием с сессией, все группы создаются сразу, лабораторные — с двумя подгруппами; студенты добавляются отдельно |
| Импорт студентов JSON по группам | Перенос списков без ручного ввода: студенты попадают в состав группы, при наличии `subjects` сразу зачисляются в несколько предметов, существующие переиспользуются по имени, оценки не затрагиваются |
| Полный бэкап — главный способ переноса | «Перенос данных» импортирует бэкап другого устройства со всеми оценками и посещаемостью; импорт студентов дополняет его |
| Выбор предмета в статистике на всю ширину | Длинные названия обрезаются с многоточием, группы переключаются бейджами ниже — фильтры не ломают вёрстку |
| Лекции не входят в итоговый балл | Для лекций нет «сдал / не сдал» и веса: только отметка «был / не был». Итог считается по практикам и лабораторным |
| «Отметить всех» доступна, но с отменой | Кнопка вернулась на основной экран сессии; ошибочное нажатие исправляется тостом «Отменить», «Максимум всем» остаётся в меню с подтверждением |
| Нижняя навигация на всех экранах | Из карточки студента или сессии можно сразу уйти в статистику/данные, не нажимая «Назад» |
| Группы переключаются бейджами | Быстрый выбор группы одним тапом; выпадающий список для этого избыточен |
| Сессии видны в журнале с датами | Тап по строке «пт, 23 окт · Подгруппа 1 · 10/11» сразу открывает выставление |
| Вкладка «Группы» вместо «Оценок» | Группа — реальная единица работы преподавателя: из неё видно состав, предметы, средний балл и путь к занятию; «Данные» перенесены в настройки |
| Группа — сущность с составом (`groupMembers`) | Студенты добавляются один раз и зачисляются в несколько предметов; старые зачисления мигрируют в состав при обновлении базы |
| Профиль студента по всем предметам | Тап по студенту в группе открывает общий профиль: предметы, средний балл, работы; журнал предмета остаётся отдельным |
| Работы группируются по виду и предмету | Одна строка на занятие, только сессии этой группы; исправлены дубли «Лабораторная 1» |
| Пример бэкапа для скачивания | Валидный JSON v2 со всеми сущностями: можно заполнить из другого источника и импортировать |
| Другая подгруппа видна на выставлении | Явка и цветные баллы второй подгруппы показываются сразу под активной, без переключения |
| Цвета подгрупп | Синий, сливовый и бирюзовый вместо красного/зелёного: подгруппа — идентификатор, а не оценка «плохо/хорошо» |
| Таблица журнала | Отдельные таблицы по видам, колонка занятия с датами подгрупп, клетка «явка + балл», липкие шапка/имена/итоги, desktop 980 px; мобильная версия — вкладки видов и внутренняя прокрутка |
| Шкала 2–5 поверх процентов | 0–50 — 2, 51–70 — 3, 71–85 — 4, 86–100 — 5; цвета красный/оранжевый/жёлтый/зелёный, порог «сдал» по умолчанию 51% |
| Одна лабораторная — несколько сессий подгрупп | Импорт расписания объединяет даты лабораторных в блоки по числу подгрупп: «Лабораторная 1» для обеих подгрупп, а не ЛР1/ЛР2 |
| Подгруппы не заданы — показывается вся группа | Сессия без подгруппы и студент без подгруппы не должны давать пустой экран |
| Номера студентов в списках | Порядковый номер в группе (по алфавиту) и в сессии — проще диктовать и отмечать |
| Удаление сущностей — soft-delete с каскадом по дочерним записям | Совместимо с LWW-синхронизацией и восстановлением |
| Excel-экспорт отложен на этап 4 | ТЗ прямо относит `.xlsx` к этапу 4; JSON уже закрывает бэкап |
| Демо-данные создаются в одной транзакции Dexie | UI обновляется один раз, а не на каждую запись |
